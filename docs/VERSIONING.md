# Versioning

## Semantic versioning

The project should use semantic versioning such as:

- v1.0.0
- v1.0.1
- v1.1.0
- v2.0.0

## Lifecycle

- ACTIVE: current recommended release
- SUPPORTED: maintained, still recommended for some users
- DEPRECATED: still available but not preferred
- BLOCKED: unsafe or unsupported, not recommended

## Release principle

Old versions must remain available for diagnostics, rollback, and historical reference while unsupported or insecure builds are not promoted as recommended downloads.
