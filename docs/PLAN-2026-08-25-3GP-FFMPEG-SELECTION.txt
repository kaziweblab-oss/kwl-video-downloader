Three work items approved for implementation:

  2. 3GP always available - ffmpeg transcode when the source lacks native 3GP

All existing features must keep working: real-time progress, true pause/resume,
cancel, retry, yt-dlp analysis, ffprobe validation, persistent history,
file-synced history, duplicate guard, sequential queue.

--------------------------------------------------------------------------------
2. WORK ITEM 1 - EXPLICIT SELECTION ENFORCEMENT (bug fix)
--------------------------------------------------------------------------------
Problem: analyze auto-selects the latest video (highlight easy to miss), so
users press Add thinking nothing is selected - and a download starts. Also
handleAddToQueue has a DEMO_ANALYSIS fallback that can queue example.com/video.

Fix:
  1. handleAnalyze no longer auto-selects a card; the analyzed list grows and
     the user must click a card (or mark it) to select. Preview + config
     unlock only after explicit selection; Add stays disabled otherwise.
  2. handleAddToQueue DEMO fallback removed - with no selection it shows
     "Please select an analyzed video first" and returns. example.com/video
     can never enter the queue again.
  3. Defense-in-depth: canAddToQueue already gates on flowAnalysis (null
     pre-selection) - unchanged.

--------------------------------------------------------------------------------
3. WORK ITEM 2 - 3GP ALWAYS AVAILABLE VIA FFMPEG TRANSCODE
--------------------------------------------------------------------------------
Flow when the source has NO native 3GP:
  yt-dlp downloads best mp4/webm (temp workspace, height filter applied)
  -> new job status "converting"
  -> ffmpeg transcode -> .3gp
  -> ffprobe validation -> completed (single history entry, unchanged)

Native (lib.rs):
  - DownloadRequestInput gains "transcode: Option<bool>" (serde default).
    Frontend sets true when 3GP is selected AND the source lacks native 3GP.
  - Transcode path uses the default best selector (height filter) with
    --merge-output-format mp4, then:
      ffmpeg -y -i in.mp4 -c:v mpeg4 -b:v 300k -vf scale=-2:H
             -c:a aac -ar 16000 -ac 1 out.3gp
    (mpeg4 + aac = ffmpeg built-in encoders, present in every build;
     AMR-NB avoided because many builds lack libopencore-amrnb)
  - ffmpeg PID is tracked in the job during conversion so Cancel (taskkill /T /F)
    works mid-conversion; temp cleanup + single history entry unchanged.
  - Source HAS native 3GP -> current direct path (no transcode).
  - New "converting" status: cart shows "Converting / konvert hocche",
    amber/cyan dot, EN/BN labels; getCartItemStatus mapping added.
  - Runtime proof required: transcode artifacts/sample-test.mp4 with the real
    ffmpeg, validate the .3gp output with ffprobe, record the evidence.

Frontend:
  - Video format list ALWAYS includes 3GP (next to MP4/WEBM).
  - 3GP + source lacks it -> transcode: true in the download request.
  - Resolution section for 3GP-transcode shows the tier's analyzed dimension
    as the scale target (scale=-2:H keeps aspect, even width).
