5. FRONTEND AUDIT - PASS (with findings A3, A8, A11)
--------------------------------------------------------------------------------
App.tsx (1102 lines):
- Session cart model with per-item lifecycle: Pending -> Queued -> Downloading
  -> Processing -> Validating -> Completed/Failed/Cancelled
- Sequential runner effect auto-starts the next queued item; re-entry guarded
  by startingItemsRef; job polling (1s) keyed on active job signature
- EntitlementService (Free audio <= 20 min) + duplicate guards at Add time
- Analyzed media list: select / mark / bulk-add / remove, dynamic format and
  resolution lists derived from real analyzed formats (not hard-coded)
- History: status dots, format badges, Open/Show-in-folder/Retry/Delete
- EN/BN translations centralized; errors sanitized via getFriendlyErrorMessage
  (no raw invoke/tauri errors leak to the UI)

tauriBridge.ts:
- Detects __TAURI_INTERNALS__ before invoke; browser mode gets deterministic
  fallbacks (app info, URL validation, demo analysis, queued job stub) and
  honest rejection for file actions - no fake success
- All payloads typed; snake_case wire format matches Rust serde structs

Findings:
- A3 (MEDIUM): Browse button is a placeholder (keeps/defaults the path); no
  native folder picker yet - requires tauri-plugin-dialog in Phase 4/5
- A8 (LOW)  : analyze_url has no timeout; a hung yt-dlp leaves Analyze pending
  (UI stays responsive; there is no Cancel for analysis)
- A11(INFO) : App.tsx is a single 1102-line file; split into components/hooks
  recommended before adding features

6. RUST NATIVE AUDIT - PASS (with findings A2, A4-A7, A14)
--------------------------------------------------------------------------------
Commands (main.rs -> lib.rs): validate_url, get_app_info, analyze_url,
start_download, get_download_job, cancel_download, get_download_history,
delete_download_history, open_media_file, reveal_media_in_explorer

Verified behaviors:
- URL validation: url::Url parse + http/https scheme allow-list
- Analysis: yt-dlp --dump-single-json (the --print json NA bug stays fixed),
  output mapped to a safe JSON payload (title/author/duration/thumbnail/
  formats with codec, dimensions, bitrate, merge flags)
- Downloads: async job registry (Mutex<HashMap>), atomic job IDs
  (timestamp + AtomicU64, covered by a 100-start uniqueness test), per-job
  temp workspace under %TEMP%\kwl-video-downloader\<job>, cleaned on every
  terminal state, --restrict-filenames, temp:-paths staging
- Progress: piped stderr parsed for percent/total/speed/ETA (deterministic
  tests incl. malformed-line rejection); [Merger]/[ExtractAudio] -> processing
- Completion: exit success -> ffprobe validation (readable stream + duration
  > 0) -> completed; otherwise failed; history written on terminal states
- Cancellation: taskkill /PID <pid> /T /F kills the whole process tree
- History: AppData\KWL Video Downloader\history.json, capped at 50 entries,
  entry-only deletion (files untouched), 3 deterministic removal tests
- File actions: canonical-path validation against persisted history or
  active-job output locations before any open/reveal (anti path-traversal)
- Entitlement defense-in-depth: native LICENSE_REQUIRED for audio > 20 min

Findings:
- A2 (MEDIUM): History timestamps use Rust debug format of SystemTime
  ({:?}), not ISO-8601; the UI cannot parse them, so timestamps never render
  in history rows and ordering is insertion-based. Recommend unix millis or
  RFC 3339.
- A4 (LOW)  : Finished job entries stay in the JOBS map until app restart
  (temp dirs ARE removed); unbounded growth is bounded in practice by
  session length but a terminal-state sweep is recommended
- A5 (LOW)  : get_app_info hardcodes name/version/environment instead of
  CARGO_PKG_VERSION / tauri config - drift risk on version bumps
- A6 (LOW)  : cancel_download on an already-finished job still flips status
  to cancelled (race window); the UI only offers cancel on active states
- A7 (LOW)  : open_media_file spawns cmd /C start (extra shell layer);
  path is canonicalized + validated first so risk is low, but direct
  ShellExecute would be tighter
- A14(INFO) : yt-dlp/ffprobe resolved by probing PATH on every call - fine
  for development; Phase 4 must switch to bundled paths only (per SECURITY.md)
